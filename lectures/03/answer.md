# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：素の LLM は講座の知識を持たないので、一般論で穴を埋めて断定に近い形で答える。エージェントは用語集という根拠を検索してから答えるので、正しく短く答えられる。そのぶん、1 つの質問で LLM を 2 回呼び、入力トークンも増える
- `--trace` で見えたツール呼び出し（ツール名と引数）：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の 2 回（`tool_calls=2`）。docstring の「query には調べたい用語を1つだけ入れる」に従い、用語を 1 つずつ検索した。どちらも第2回の用語として定義が返った
- 1つの質問での LLM 呼び出し回数（`requests`）：2 回。ツール呼び出しは 2 回あったが、1 回目の応答で 2 つの検索をまとめて依頼したので、ツールの結果を受け取って答える 2 回目と合わせて 2 回で済んだ
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int) -> str`。用語集から指定した回の用語を 1 つ選び、`{"question": "「…」の意味は？", "answer": <定義>}` を JSON 文字列で返す（その回の用語が無いときは、用語がある回の一覧を返す）。docstring には「指定した回の用語から 1つを選び、確認問題と答えを返す。」「「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。」と、何を返すかと使う場面を書いた

## 宿題

- 取り組んだレベル：発展（a）ADK で作り直す
- やったこと：`adk_agent/glossary_agent/agent.py` で、演習と同じ `INSTRUCTIONS` とツール（`search_glossary`・`get_lecture_summary`・`make_quiz`）を ADK の `Agent` に渡して `root_agent` を作り、`adk run` で動かした。モデルも演習と同じ `app.config.MODEL`（`gemini-3.5-flash-lite`）にそろえた。`adk run` の画面にはツール呼び出しが出ないので、演習の `--trace` の代わりとして `adk_agent/glossary_agent/trace.py` も作った。ADK の `InMemoryRunner` でエージェントに質問し、返ってきたイベントからツール呼び出し（ツール名と引数）・ツールの結果・回答を表示するスクリプトで、`uv run python -m adk_agent.glossary_agent.trace` で実行する。そのうえで、演習と同じ質問「LoRAとQLoRAの違いは？」を両方のエージェントに投げて比べた
- 結果：
  - 書き方の違い：Pydantic AI 版は `Agent(instructions=...)` を作ってから `agent.tool_plain(...)` でツールを 1 つずつ登録し、モデルは `run_sync(..., model=...)` で実行時に渡す。ADK 版は `Agent(model=..., name=..., instruction=..., tools=[...])` のように、モデル・名前・指示・ツールを作るときにまとめて渡す。どちらも普通の関数をそのまま渡し、docstring と型ヒントがツールの説明になる点は同じなので、`app/tools.py` は変えずに使えた。実行のしかたも違い、Pydantic AI 版は自分で書いた CLI（`python -m app.agent`）、ADK 版はフレームワークの `adk run`（対話式）で動かす
  - ツール呼び出し：ADK 版も `search_glossary` を `LoRA` と `QLoRA` で 1 回ずつ、計 2 回呼んだ。演習の `--trace` と同じ呼ばれ方だった（`trace.py` で確認）
  - 回答の違い：中身はどちらも用語集の定義に沿っている。LoRA は「重みを固定して低ランク行列だけを学習する」、QLoRA は「ベースモデルを4ビットなどに量子化してメモリを節約する」と説明し、最後に第2回を示した。違いは書き方で、Pydantic AI 版は「Low-Rank Adaptation」「PEFT（Parameter-Efficient Fine-Tuning）」と略語を展開し、「学習するパラメータ数を大幅に減らせる」と補足していて、やや詳しい。ADK 版は「講座の用語集によると」と根拠を先に示し、短くまとめていた。また、指示では「関係する回」と書いているのに、ADK 版は「関連する回」と言い換えていた
- 気づき・疑問：指示・ツール・モデルが同じなら、フレームワークを替えてもツールの呼ばれ方と回答の中身はほぼ同じだった。エージェントの振る舞いを決めているのはフレームワークではなく、指示とツールの説明（docstring）だと分かった。回答の長さや言い回しの違いは、同じエージェントを何度か実行したときのばらつきの範囲かもしれず、1 回ずつの比較ではフレームワークのせいかどうか判断できない。フレームワークの違いが大きく出るのは、トレースの見え方、実行のしかた（自作の CLI か、`adk run` か）、会話の記録の保存（ADK はセッションを自動で保存する）など、エージェントの周りの部分だと感じた。ADK のように会話がセッションとして保存されると、続けて質問したときの回答がどう変わるのかが疑問として残った

### 補足：実行結果

同じ質問「LoRAとQLoRAの違いは？」への、両方のエージェントの出力（回答部分）。

**ADK 版**（`PYTHONPATH=. uv run --with google-adk adk run adk_agent/glossary_agent`）

```text
[glossary_agent]: 講座の用語集によると、LoRAとQLoRAの違いは主に次の点にあります。

* **LoRA**: 事前学習済みの重みを固定したまま、重みの更新分を2つの小さな行列の積（低ランク行列）で表し、その小さな行列（パラメータ）だけを効率よく学習する手法です。
* **QLoRA**: LoRAの仕組みをベースにしつつ、ベースモデルの重みを4ビットなどに**量子化**して省メモリ化し、より小さなGPUでも大きなモデルを学習・扱えるようにした拡張手法です。

関連する回：第2回
```

**Pydantic AI 版（演習のエージェント）**（`uv run python -m app.agent "LoRAとQLoRAの違いは？"`）

```text
**LoRA**と**QLoRA**の違いは、ベースモデルの重みを量子化するかどうか、およびそれに伴うメモリ節約の度合いにあります。

* **LoRA（Low-Rank Adaptation）**
  事前学習済みの重みを固定したまま、重みの更新分を2つの小さな行列（低ランク行列）で表し、その小さな行列だけを学習するPEFT（Parameter-Efficient Fine-Tuning）手法です。学習するパラメータ数を大幅に減らすことができます。

* **QLoRA（Quantized LoRA）**
  ベースモデルの重みを4ビットなどに**量子化**してメモリをさらに節約したうえで、LoRAと同様に低ランク行列を学習する手法です。これにより、より大きなモデルをより小さなGPUメモリで扱えるようになります。

関係する回：第2回
```
